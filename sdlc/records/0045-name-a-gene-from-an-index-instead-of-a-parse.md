# Name a gene from an index instead of a parse

Naming no longer costs a command-line lookup twenty-five times its own runtime. `assets/gene-names/gene-names.pgn` is a built index embedded in the executable, and a lookup reads only the bytes one accession touches. Resolving eight accessions from a cold process costs 62 microseconds against the ticket's 1 millisecond budget. Naming adds 7 microseconds to a warm render. The whole-file parse that took 155 milliseconds is gone, along with `pangopup assets naming install`, the `naming` object on `/v1/status` and `crates/pangopup-assets/src/naming.rs`.

The format is `PGNAME01`, 2,319,183 bytes, SHA-256 `e34dfa717eb90accbe9a61327d330ce046f626a152426de7bec3d11062e692b3`. A 128-byte header carries the magic, the version, the header size, the file length, section descriptors and counts in the same byte positions the SNV index uses. Three sections follow: a sorted key array of accession numbers at stride 8, a parallel 24-byte record array addressed by the same index, and a string section holding each gene's symbols as one contiguous run of length-prefixed strings. A lookup is one binary search, one record read, one string-run read.

The index takes its shape from `crates/pangopup-index/src/snv.rs`. It adopts explicit little-endian decoding with mapped bytes never cast to a Rust struct, fixed strides addressed by index times stride, page accounting at 4096 bytes, and a canonical-structure check proving the sections are contiguous with no padding. It drops the interval tree and the per-contig roots, because a naming key is one accession and not an interval. It drops the exceptions section, because a withheld name is one byte on the record it belongs to. It does not deduplicate strings: 106,198 slots against 102,426 distinct strings saves 3.5 per cent and costs an indirection, a section, an invariant and a scattered page touch per symbol.

The index carries 46,587 accessions. HGNC names 42,355 of them, NCBI names 4,184 that HGNC does not reach, and 48 report no name. Against the installed mask this raises named scoreable genes from 41,954 to 44,540 and lowers unnamed from 18,651 to 16,065. HGNC supplies a whole record wherever it names an accession and NCBI is not consulted for it, so the 105 accessions where the two sources report different NCBI Gene identifiers and the 125 where they report different symbols need no arbitration. An accession carrying more than one record in its naming source reports no name. A gene NCBI names reports no HGNC identifier even though 961 of them carry one in NCBI's own cross-references, because HGNC publishes no join to that accession. Alias symbols come from both sources and previous symbols come from HGNC alone, because `Homo_sapiens.gene_info` has no previous-symbol field.

`make gene-name-index` downloads both sources, builds the index, writes it to its committed path and reports the digests and row counts it built from. It reaches the network and no gate invokes it. `assets/gene-names/provenance.json` records both sources with byte counts and digests, and states that the NCBI source is not re-fetchable at those bytes. NCBI replaces `Homo_sapiens.gene_info.gz` daily at a fixed URL and publishes no dated archive, so the committed index is the only durable record of what named a gene.

Independent design and code reviews accepted the result after repairs, and each caught one defect that would have shipped a wrong answer.

The design keyed the index on a `u32`. `ENSG05220017861` is an approved HGNC record, `HGNC:37104`, `DDX11L3`, whose numeric form is 5,220,017,861. That exceeds `u32::MAX` and truncates into a collision with `ENSG00925050565`, so one accession in 46,587 would have answered as a different gene. The design review widened the key to `u64`, added the real row to the fixture, and authored a test that a `u32` implementation fails.

The design's page assertion did not guard the regression the ticket exists to prevent. It measured pages touched per lookup, starting after the index was open, so a reader that decoded the whole index into a map at open would attribute zero pages to every lookup and pass. The design review moved the measurement to run from a fresh open through the answer and added a floor beside the ceiling. The code review then proved both bounds by breaking the reader twice: an eager decode reported 365 pages against a ceiling of 16, and answering from a structure built beside the index reported 1 page against a floor of 2.

The code stage made the same variant render differently depending on the flag that chose the bundle. `--bundle` reported no names and `--data-dir` reported them, from one executable holding one embedded index. The stated reason was the cost of restating 12 spec assertions and 7 fixture oracles. The code review overturned it. The rule had a cause when the naming source lived in the data root, and this design removed that cause and kept the rule. `Rendering.names` now takes `&GeneNameIndex` rather than an `Option`, so the divergence is unrepresentable. The accepted cost is that 12 specification assertions pin real gene names and a future naming refresh that renames `WRAP53`, `TP53`, `TSPAN6` or `CD4` breaks them. The seven regression oracles keep no names and gain a guarded strip step instead, because their generator never calls the renderer and coupling them to a naming vintage would destroy their independence.

The code review also found a release blocker already in the tree. `scripts/check-production-qualification.py` compared release output byte for byte against fixtures carrying no gene names, so the real production qualification would have failed on four comparisons while `make test` stayed green. `tests/production-release-qualification.sh` exercises the checker through a stubbed binary and cannot see the difference. The checker is repaired and now carries three negative cases proving it rejects unnamed output. Draft 0046 records the shape that remains.

`.dockerignore` denies everything and allowlists individual paths, and the `Dockerfile` copied only `assets/notices`, so the index could not have reached the container build. Both are corrected. The code review built the image and confirmed the container answers a lookup with a gene name.

One build carries one naming vintage, so a retained record's labels are traceable through `data_set_version`, which already hashes the software version. That closes draft 0044. The accepted cost is that a consumer refreshes gene names by upgrading PangoPup. The release executable grows about 2.2 MiB on 38.5 MB.

No published identity moved. `crates/pangopup-assets/src/active_identity.rs`, `crates/pangopup-assets/src/error.rs` and `crates/pangopup-build/src/source_fingerprint.rs` are byte-identical to the base commit, so `scoring_identity`, `data_set_version`, `runtime_profile_id` and the published builder fingerprints are unchanged. The published executable and container pins stay at v0.4.1.

The index rebuilds from its sources to the byte. An independent decoder and an independent reimplementation of the merge, both written in Python, agree with the shipped file on all 46,587 entries.

`make lint`, `make test` and `make spec` passed with 542 tests passing, 9 ignored, and 302 specifications passing with 7 retained-asset specifications skipped by design. The lifecycle suite behind the non-default feature, which carries this ticket's naming proofs, passed all 13 of its tests.
