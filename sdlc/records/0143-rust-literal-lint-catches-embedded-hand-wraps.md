# Rust literal lint catches embedded hand wraps

The Rust literal continuity gate now follows the lexical states that can change a quote's meaning. It rejects an unescaped physical newline in an ordinary, byte, or C string and retains the existing rejection of three or more spaces between word characters inside those strings. A trailing backslash remains an accepted continuation. Character and byte-character literals, lifetimes, labels, line comments, nested block comments, and raw, raw-byte, and raw-C strings with exact hash delimiters cannot create false string boundaries. Unterminated strings, character literals, and block comments report their path and opening line.

The first red run added draft 0103's two-line ordinary literal to the old harness. The old line-oriented check exited 1 because its own fixture assertion reported that it did not refuse `crates/other/src/embedded-wrap.rs`. The repaired fixture set pins that miss, the prior collapsed-space finding, ordinary and byte continuations, escaped quotes and backslashes, a character containing `"`, lifetimes, labels, comments, C strings, and raw delimiters that close only on the matching hash count.

Eighteen exact exemptions preserve the aligned `LEGACY_USAGE` value and the repository's seventeen deliberate multiline SQL literals. Each exemption binds a finding kind, path, line, and complete opening source line. A copied value, a defective neighbor, or a moved, removed, or changed exemption target fails. The supported grammar and its boundary are recorded in `tests/support/rust-literal-scan.md`.

The first independent code review rejected the candidate on three work and portability gaps. A single 59,813-byte line with 2,000 ordinary and 2,000 raw literals charged 300,276,036 work units because each opening trimmed the whole line and each raw literal copied the remaining suffix. Rust-valid CRLF and whitespace-only continuation lines produced three false findings. A source containing `const CHAR: char = 'é';` and the rustc-valid lifetime `'é` made macOS Awk stop on a multibyte conversion failure.

The repaired scanner computes the trimmed opening once per line, walks raw contents in place, and caps delimiters at Rust's 255-hash grammar limit. Its test-only accounting charges copied line bytes, state-machine steps, continuation whitespace, and raw-delimiter comparisons. The same 4,000-literal line now uses 117,624 work units for 59,813 bytes under a twelve-units-per-byte gate. CRLF normalization and a continuation-whitespace state preserve Rust's blank-line behavior. The harness fixes Awk to the C locale and advances character literals by validated UTF-8 byte width. Rustc compiles the checked CRLF, blank-line, Unicode character, and Unicode lifetime fixtures.

The second independent code review found that macOS Awk could still rescan or copy the full line for repeated `length`, `substr`, and scalar function arguments. The accounting did not charge those operations. The scanner also treated the invalid forms `'!`, `' `, and `b'!` as lifetimes. Rustc rejects them with E0762 or E0763. Finally, the continuation state used the locale space class and skipped vertical tab and form feed, although Rust retains those bytes in the literal.

The final scanner splits each physical line into a byte array once, caches its length, and passes only positions or single bytes through per-byte helpers. It copies the trimmed opening text once. Accounting now charges the complete line scan, byte-array copy, opening copy, state-machine work, continuation bytes, and raw-delimiter comparisons. Single lines with 500, 1,000, and 2,000 ordinary/raw literal pairs used 57,240 work units for 14,311 bytes, 115,248 for 28,813 bytes, and 239,248 for 59,813 bytes. Each result stays near four work units per byte and below the fixed twelve-unit bound. The harness limits continuation skipping to space, tab, carriage return, and line feed. It pins vertical tab and form feed as retained newlines. Lifetime classification now requires an ASCII identifier start or a structurally valid multibyte UTF-8 scalar. The scanner and rustc both reject the original three malformed apostrophe fixtures.

The third independent code review found that the scanner reached the general apostrophe path after the `b` in unterminated `b'a` and `b'_` forms. That path admitted `a` and `_` as lifetime starts, although a `b'` prefix starts a byte-character token. The old scanner missed both new red fixtures while rustc rejected each with E0763. The scanner now recognizes the byte-character prefix before general apostrophe handling and disables lifetime fallback in that context. A valid ASCII byte character, Unicode character, ASCII lifetime, and Unicode lifetime remain positive fixtures.

The focused Bash 3.2 gate checks 108 Rust sources and a generated 1,402,788-byte line corpus. `make lint`, `make test`, `make spec`, and `git diff --check` passed on macOS. The specification gate ran 205 blocks. The scanner remains a bounded lexical check. It does not parse Rust expressions, macros, types, or names. Draft 0103 is archived with this ticket.
