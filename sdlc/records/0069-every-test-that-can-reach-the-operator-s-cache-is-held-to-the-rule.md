# Every test that can reach the operator's cache is held to the rule

The model cache is on by default and its directory comes from `XDG_CACHE_HOME`, or from `HOME` when that is unset. A test that spawned the shipped executable without redirecting both reached the cache file of whoever ran the suite, and since ticket 0058 a cache whose recorded setup no longer matches is discarded rather than ignored, so such a spawn destroyed that file rather than only growing it. Ticket 0059 redirected one test file and proved it for that file alone. Whether any other spawn reached a cache depended on which subcommand it happened to call.

The rule is structural now. `crates/pangopup-cli/tests/support/mod.rs` is the one place a test may name the shipped executable, and every command it builds gets a private cache home of its own, held open until the process it belongs to has exited. Five test sources, one benchmark and the runtime proof route through it. `tests/cli-spawn-cache-isolation.sh`, added to `make test`, reads the calling side: it refuses any other Rust source in the repository that names `CARGO_BIN_EXE_pangopup`, or that reaches the executable by path through `current_exe` or `target/{debug,release}/pangopup`. It reports what it examined, so a scan that matches nothing fails rather than passes, and it exercises six refusals and two acceptances against fixture trees before it reads the real one. `crates/pangopup-cli/tests/spawn_isolation.rs` reads the other side, asserting that a command the helper built resolves neither the ambient `XDG_CACHE_HOME` nor the ambient `HOME`. Neither half proves the rule alone.

The boundary held. No product source changed. The cache still lives at `$XDG_CACHE_HOME/pangopup/model-results.sqlite3`, is still on by default, and falls back to `$HOME/.cache` unchanged. No test assertion about scoring was weakened, added or removed. `XDG_CACHE_HOME` was not moved for the `cargo test` step. The per-spawn redirection commit `5393f44` added to `model_routing.rs` is performed by the helper now, identically.

Verified with `HOME`, `XDG_CACHE_HOME` and `TMPDIR` inside a scratch directory whose cache home was created empty. A full `make test` left no `pangopup` path anywhere under either — no cache directory, no cache file, nothing. The only entries the whole ladder added to that cache home were the ONNX Runtime static library the build script fetches and a Python tool cache, neither of them the product's. Run by hand under a private cache home, `pangopup lookup` with a model bundle wrote `pangopup/model-results.sqlite3` there, and with `XDG_CACHE_HOME` unset it wrote `.cache/pangopup/model-results.sqlite3` under the private `HOME` instead, which is why the helper sets both. Detours planted in a crate that has no test directory today, in another crate's `benches/`, in a `support/` sibling that is not `mod.rs`, and spelled against the release profile rather than the debug one were each refused by file and line. Removing the helper's `HOME` line, and pointing the helper back at the ambient home, each turned `spawn_isolation` red with a message naming what it found. The one step added to `make test` costs 0.39 seconds over three runs.

One repair landed here. The detour scan exempted `/src/`, which matched any directory named `src` anywhere, so a detour under `crates/pangopup-cli/tests/src/` was accepted at exit 0. The exemption now reads `/crates/*/src/` and that detour is a fixture the scanner refuses before it reads the real tree.

`crates/pangopup-cli/tests/macos_cli_boundary.rs` is `#![cfg(target_os = "macos")]`. Its two converted spawns were type-checked and never executed, here or in any earlier stage; `.github/workflows/ci.yml:185` is the only place that file runs.

The helper hands the caller the `Command` it built, so a caller can set `XDG_CACHE_HOME` again afterwards and replace the private path. Both of this ticket's assertions stay green when it does. Every caller that overrides today points at a directory the test owns, and reaching the operator's cache would take reading `HOME` out of the suite's environment and passing it back, which is a deliberate act rather than a lapse of habit. Closing it means the helper stops handing out a raw `Command` and takes a typed cache home instead. That is accepted as it stands and is not open work.

One finding stays open as a draft. 0071 records that the shell qualification harnesses run the executable directly, outside a gate that reads `*.rs` only.
