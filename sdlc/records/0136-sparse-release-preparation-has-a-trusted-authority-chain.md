# Sparse release preparation has a trusted authority chain

Maintainer tooling now assembles a sparse bundle only after authenticating the exact immutable fixed-v1 corpus authority. The sparse manifest inherits and rechecks attribution, source, reference, counts, and logical identities. It records the candidate-producing commit, the original authority builder, the current assembler version, and a new fingerprint over the sparse byte-producing path. Fixed-v1 parsing, production release preparation, remote sync, and active authorities remain unchanged.

Sparse transport keeps the established encoder and part limits. Local v2 preparation fully verifies and reconstructs the transport, exhaustively certifies the bundle, requires the executable's compiled clean Git commit, keeps the later release target separate, and produces canonical proof, profile, checksum, notes, and explicit SNV-only size sums. Miniatures reproduce every byte twice and install only under an isolated temporary root.

Independent design review rejected the original retained-data scope until tooling and evidence were split. Independent code review rejected forged authority and tooling claims, relative-path publication failure, unsafe stage replacement, and wrong builder version. A second review found a remaining check-to-rename race. The accepted implementation authenticates complete authority facts and tracks directory ownership through post-rename identity verification. `make lint`, `make test`, `make spec`, and `git diff --check` passed on macOS. The specification gate ran 199 blocks.
