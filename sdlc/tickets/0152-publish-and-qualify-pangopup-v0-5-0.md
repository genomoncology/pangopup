# Publish and qualify PangoPup v0.5.0

## Outcome

One exact main commit is the immutable public PangoPup v0.5.0 source tag, Linux executable release, and native AMD64/ARM64 container index, and the public artifacts pass fresh installation and upgrade qualification.

## Done, observably

- Freeze the exact clean pushed main commit after all dependencies. Release text, version checks, citation date, installer, compatibility inventory, and changelog agree on v0.5.0 and the public v2 scoring assets.
- Local gates and required pushed-commit CI pass. Stage the executable and native container leaves through the reviewed workflows. Authenticate source commit, inventories, checksums, software bill of materials, platform, dynamic libraries, and the public v0.4.1 container predecessor before publication.
- Publish the six-file executable release and source tag once. Finalize one public native AMD64/ARM64 container index and move only the v0.5.0 aliases and `latest` to that index. Preserve every older tag and digest.
- Fresh anonymous downloads and pulls match the admitted bytes and source revision. The tagged installer, clean sync, offline reuse, status, lookup, model, cache, HTTP, code-only uninstall, and full uninstall checks pass.
- Qualify a real v0.4.1-to-v0.5.0 upgrade. The SQLite layout-1 cache is discarded once, layout 2 records software version 0.5.0, the request is recomputed, and the next identical request is a cache hit. The sparse-index switch preserves compatible model-cache rows. Database observations contain no SNV bundle or rendered response identity fields.
- Public SNV and model results retain exact two-decimal scores. Status and every HTTP result report independently derived `data_set_version` and `scoring_identity`; cached results receive the current response identities.
- Add a durable publication record with run, release, artifact, tag, digest, inventory, qualification, and cleanup evidence. Mark the changelog released and update the frontier. Final repository gates pass from the recorded public commit or its documentation-only descendant.

## Boundary

Publish the already accepted v0.5.0 product only. Do not change scoring behavior after qualification, introduce three-decimal output, delete old releases, add indel precomputation or threshold triage, or modify downstream consumers.
