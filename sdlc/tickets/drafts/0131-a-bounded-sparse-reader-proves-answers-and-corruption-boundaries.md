# A bounded sparse reader proves answers and corruption boundaries

The candidate `pangopup.sparse-direct.v1` writer now produces deterministic bytes, but nothing in the repository can safely read them. A complete build would produce an unqualified artifact until an independent reader proves exact lookup, complete traversal, and the corruption boundary required by ADR 0027.

Build a candidate-only memory-mapped reader for the existing writer format. Keep fixed-v1, bundle opening, manifests, profiles, installed assets, and runtime routing unchanged.

## Acceptance

- Opening validates the magic, version, header length, exact file length, section order and adjacency, fixed entry sizes, checked count products and sums, directory ordering and unique complete ownership, segment and block coverage, payload ranges, exception ordering, and every reserved metadata byte. It validates typed genes, contigs, and coordinates. It rejects overlapping ordinary segments within one gene and contig, exceptions without a declared gene, and an exception that overlaps an ordinary locus for the same gene. Malformed metadata, truncation, bad offsets or counts, and arithmetic overflow fail without panic or unbounded allocation.
- Opening does not scan ordinary score payloads. Test instrumentation sits on the reader's actual ordinary-payload accesses and proves that opening reads zero payload bytes. A successful lookup is the positive control that proves the counter moves. Opening may validate the fixed-size directories and exception section.
- Exact lookup supports all overlapping genes in canonical order and an optional gene filter. An ordinary reference mismatch returns no ordinary record. It is not a separate result. `REF=N` exceptions return ambiguity records. Lookup validates the touched block before returning for a reference mismatch.
- Lookup validates the selected block before returning any result. It validates the block header and length, every rank checkpoint, the complete active and mask arrays, unused packed tail bits, active and pair counts, and consistency between active flags and masks. It validates reserved pair bits, score magnitudes, positions, and all gain/loss pairs for all alternates at the addressed locus. It need not decode unrelated pair values elsewhere in the same block; `verify_all` validates them. Corruption in an unrequested alternate at the addressed locus therefore fails the lookup.
- Lookup may leave an untouched ordinary block unread. A mutation in that block may survive open and an unrelated lookup. `verify_all` must detect it.
- A canonical `visit_all` traversal emits every locus, every ordered alternate, overlap order, scores, positions, and `REF=N` exception in the same logical form as the writer input. An independent miniature source oracle compares the complete stream. The cases include a gene containing only exceptions and a file containing only exception loci; fixed-v1 traversal is not the oracle for those cases.
- Tests cover coordinate gaps and overlaps, multiple genes and contigs, block and 64-locus rank boundaries, default records, zero scores with nondefault positions, partial masks that differ by alternate, reference mismatch, pure misses, filtered overlap, every reference base, both exception shapes, exception-only genes and files, and the maximum coordinate.
- Mutation tests separately cover every header and directory field, every reserved region, rank entries, flags, masks, unused tail bits, touched pairs, untouched pairs, truncation at section and record boundaries, and values chosen to exercise checked arithmetic. Malformed encodings must fail at the declared open, lookup, or `verify_all` tier. A valid score encoding changed to another valid score is not detectable corruption in this unauthenticated file; it must change the independent oracle comparison. Full-corpus digest equality remains a later qualification gate.
- The reader does not allocate state proportional to the complete locus or score count. `visit_all` streams without retaining a complete gene or corpus and validates each block once per traversal. A focused single-process tracking-allocator test compares generated corpora with the same directory shape and increasing locus counts. From reader creation through traversal with a nonallocating visitor, added peak heap must stay at or below 1 MiB and retained heap after traversal must stay at or below 64 KiB, excluding the memory mapping itself.
- Gene-filtered lookup uses the gene-ordered directories. The implementation record states the chosen complexity for filtered and unfiltered lookup and whether selected-block validation repeats across calls. Later side-by-side measurements, not this ticket, decide whether that complexity satisfies ADR 0027 latency gates.
- `architecture/index.md` documents what open validates, what lookup validates, and what only offline verification validates. It continues to call the format a candidate with no installed asset or runtime route.
- Focused tests, `make lint`, `make test`, `make spec`, and `git diff --check` pass on macOS. The exact pushed code also passes the focused reader tests on Linux AMD64.

## Excluded

Do not build the complete genome candidate, benchmark latency, add a bundle profile, change identities, activate routing, change score precision, or claim any ADR 0027 release gate. Those steps depend on this reader but belong to later tickets.
