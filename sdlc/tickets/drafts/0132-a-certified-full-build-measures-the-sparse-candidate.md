# A certified full build measures the sparse candidate

The sparse writer and reader pass bounded miniature tests. The repository still has no reusable path that transforms the certified complete fixed-v1 bundle into one complete candidate. The estimated sparse size is not release evidence.

Add a maintainer-only candidate builder and run it against the retained certified fixed-v1 bundle. Keep every runtime profile, installed asset, identity, and route unchanged.

## Acceptance

- The builder accepts explicit fixed-bundle, scratch, candidate, and report paths. It refuses existing scratch, candidate, and report paths and never overwrites them.
- It opens the exact three fixed-bundle members as held regular-file descriptors, validates the member set, and carries the existing exhaustive fixed-v1 certification onto those same descriptors. Certification includes the closed manifest, embedded NOTICE bytes, existing member-size ceilings, member hashes, canonical fixed structure, equality of `logical_source` and `logical_decoded`, complete decoded logical equality, and all decoded count checks. Path replacement cannot make authentication and traversal refer to different bytes. The retained command additionally requires the expected complete bundle identity.
- Add a bounded complete-gene traversal to the fixed reader. It preflights each gene's ordinary and exception counts before reserving memory, rejects more than 3,000,000 loci or 512 MiB of allocated `InputLocus` capacity with checked arithmetic, materializes only that gene, and gives its slice directly to `SparseIndexWriter`. The builder does not create a second gene buffer. The report records the maximum buffered length, capacity, and allocated capacity bytes. Tests prove the guard fires before an oversized allocation.
- It opens the completed candidate with `SparseIndexReader`, runs complete offline verification, computes the same canonical decoded digest through `visit_all`, and requires fixed, candidate, and manifest decoded record counts and digests to match exactly.
- Candidate hashing and `SparseIndexReader::open_file` use the same held staged file. Publication links that verified inode, checks the published inode against the held descriptor, and never trusts a reopened staging pathname. Held input and candidate files must remain immutable for the complete run. Tests replace the candidate staging path after descriptor capture and require safe failure or publication of only the held verified inode.
- Candidate and report publication is no-replace but cannot be one atomic operation. The candidate is linked and directory-synced first. The report is the completion marker and is linked and directory-synced second. If report publication or either required directory sync fails, the builder removes the candidate and report only when each path still names its builder-owned inode, syncs the affected directories, and reports cleanup failure without hiding the original error. Replaced paths remain untouched.
- The closed deterministic `pangopup.sparse-candidate-report.v1` JSON report records the input bundle identity and fixed member identity, candidate format, bytes, SHA-256, writer and decoded counts, both logical digests, maximum buffered gene length, capacity and bytes, and whether the 3,221,225,472-byte ADR 0027 size gate passed. RFC 8785 canonical bytes make identical facts byte-identical. Paths, timestamps, host details, elapsed time, and resident memory stay outside this report.
- Miniature tests cover exact success, deterministic candidate and report bytes, validly rehashed manifests with wrong counts, wrong logical-source digest, wrong decoded digest and wrong NOTICE, path replacement after input and candidate descriptor capture, member corruption, logical mismatch, pre-allocation gene limits, existing-path preservation, both publication boundaries, directory-sync and cleanup failures, and owned-file cleanup. They include collision and cleanup for the sparse writer's derived exception scratch path.
- The full retained run uses the certified bundle already present under `data/pangopup/runtime-v0.5.0`. Record the exact input bundle identity, fixed and candidate byte sizes and hashes, gene/locus/exception counts, logical digest, maximum buffered gene measurements, size-gate result, command commit, platform, and peak resident memory in `sdlc/records/0132-certified-full-sparse-candidate.md`. Keep the candidate and report under `data/pangopup`; do not install or activate them.
- The implementation belongs to `pangopup-build`. `architecture/index.md` documents its maintainer command, immutable-file requirement, report schema, output locations, and candidate-only status.
- Focused tests, `make lint`, `make test`, `make spec`, and `git diff --check` pass on macOS. The exact pushed builder commit passes its focused miniature tests on Linux AMD64 before the full retained run.

## Excluded

Do not benchmark lookup latency, change the candidate format, add a bundle or runtime profile, change identities, activate routing, alter score precision, or claim full ADR 0027 qualification. Size and complete logical parity are the only release gates measured here.
