# Bounded shell scan

`shell_scan.py` gives the negative-assertion, built-executable, and pipeline gates one view of repository shell programs. Discovery reads Git's tracked paths in byte order. It includes every regular `*.sh` file and every other tracked regular file whose first line uses `/bin/sh`, `/usr/bin/sh`, `/bin/bash`, `/usr/bin/bash`, or `env sh|bash`, with optional interpreter arguments. It excludes `.git` and `target` path components. File mode does not affect admission.

The lexer supports comments, escaped newlines, multiline single, double, and ANSI-C quotes, parameter expansion, arithmetic regions, backticks, command and process substitutions, quoted and unquoted heredocs, tab-stripping heredocs, functions, grouped commands, `case`, `if` and `elif`, `while` and `until`, and the normal list operators. Token kind remains distinct from token text, so a quoted `|`, `;`, or reserved word stays a command word or argument. Executable substitutions inside parameter expansions, arithmetic, process substitutions, and unquoted heredocs are scanned. Quoted heredoc bodies and ordinary quoted text remain data.

The build check accepts direct invocation of `scripts/require-built-commands.sh`, invocation through `bash`, `sh`, `source`, or `.`, and a static variable binding invoked later without reassignment. Single-quoted variable text remains inert; double-quoted expansion executes. It recognizes `name()`, `function name`, and `function name()` declarations and analyzes a function body only when a proven call reaches it. Target uses and executable substitutions inside a called function remain visible. An uncalled function, a later builder, and a builder in unproven control flow earn no credit. Assignment, reassignment, `unset`, and `read` update or invalidate the static binding. Unproven control flow that can change the answer receives a path, line, and reason.

The pipeline check follows every command in a grouped or subshell right-hand stage. It recognizes the documented early readers despite ordinary option ordering, including `grep -e pattern -q` and `sed -n -e1q`. The repository modes all refuse lexical or structural diagnostics relevant to their answer.

The parser does not execute expansions, follow `eval`, infer generated shell, or prove arbitrary control flow. It refuses command and parameter expansion nesting beyond 64 levels and function call or summary depth beyond 128 calls. Builder analysis memoizes function-effect summaries. It allows at least 1,024 proven function calls and then caps expansion at 64 times the parsed command count. It also caps processed commands at the larger of 4,096 commands or 128 times the parsed command count. These bounds prevent recursive or repeatedly expanded input from consuming unbounded or superlinear work. Malformed quotes, substitutions, parameter expansions, redirections, functions, and heredocs fail with a path and line. `tests/shell-scanner-coverage.sh` pins the supported grammar, path set, positive controls, and each refusal shape.
