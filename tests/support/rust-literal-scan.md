# Rust literal continuity scan

`rust-literal-scan.awk` gives `tests/rust-literal-continuity.sh` a bounded lexical view of Rust source under `crates/`. It refuses an unescaped physical newline inside an ordinary, byte, or C string. It also refuses three or more spaces between word characters inside those strings. A final backslash continues an ordinary line. The scanner normalizes CRLF and keeps discarding continuation whitespace across empty or whitespace-only physical lines until the first non-whitespace byte, as Rust does.

The scanner tracks ordinary strings, escaped quotes and backslashes, character and byte-character literals, lifetimes and labels, line comments, nested block comments, C strings, and raw, raw-byte, and raw-C strings with exact hash delimiters. Raw-string contents remain data. An unterminated ordinary string, raw string, character literal, or block comment fails with its path and opening line. The shell fixes `LC_ALL=C`, so Awk positions always count bytes. The scanner advances over structurally valid two-, three-, and four-byte UTF-8 scalars when it distinguishes a character literal from a Unicode lifetime. A `b'` prefix selects byte-character handling and cannot fall back to lifetime handling. Rustc fixtures compile valid character and lifetime forms and reject the pinned malformed forms. The scanner does not parse Rust expressions, macros, types, or names.

`tests/rust-literal-continuity-exemptions.tsv` names every deliberate finding by kind, path, line, and exact opening source line. The existing aligned `LEGACY_USAGE` value and the current multiline SQL literals are the complete list. A moved, removed, or changed literal leaves a stale exemption and fails. A nearby literal receives no exemption.

The scanner splits each physical line into a byte array once and caches its length. Per-byte loops index that array. They do not call `length` or `substr` on the complete line. The scanner copies the trimmed opening text once per line, advances through raw contents in place, and bounds raw delimiters at Rust's 255-hash limit. Its optional test-only accounting charges the complete line scan and byte-array copy, the opening-text copy, each state-machine step, skipped continuation byte, and bounded raw-delimiter comparison. The coverage harness measures single lines containing 500, 1,000, and 2,000 ordinary/raw literal pairs. All three stay below twelve work units per source byte, and each larger fixture stays within ten percent of the preceding fixture's work-per-byte rate. It also scans a generated 1,402,788-byte line corpus. The shell harness uses features available in Bash 3.2, and the scanner uses POSIX Awk features.
